# Planet sector ingestion (v0.23.0)

The Planet event payload now includes `sector`. The writer accepts both quoted
protobuf uint64 values and JSON numbers, and permits `127`, `999`, `44`, or the
legacy default `0`. Values outside that set fail before database writes.

Apply structs-pg's `planet-sector-20261110` Sqitch migration before this writer.
The mandatory schema contract checks `structs.planet.sector` and
`view.planet.sector` as smallint; optional doctor checks also check the source
column. Canonical schema stays Sqitch-owned, not bootstrap-owned.

Install the schema and writer before the chain upgrade so its normal Planet
backfill events populate existing rows. A sector-only change updates the source
row; identical replay makes no redundant UPDATE. Old payloads without the field
write zero, preserving ordered historical replay semantics. Do not manufacture
assignments in SQL or infer them from the current block hash.

The existing planet SQL view exposes sector without changing earlier columns.
Webapp serializers/UI are outside this writer/database change. If an old writer
already consumed the upgrade events, recover through the supported event replay
procedure rather than expecting a restart at the current tip to backfill them.

Tests: full `go test ./...` (optional database tests skip without a DSN), binary
build, and real PostgreSQL tests `TestHandler_Planet`,
`TestHandler_PlanetSector`, and `TestEconomySchema_PlanetSectorRequired` passed on
November 10, 2026. The integration instance was disposable and schema-only;
no running writer or database was migrated/restarted. The paired structs-pg
migration lifecycle test also passed deploy, verification, revert and redeploy.
